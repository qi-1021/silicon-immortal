# 核心设计台指南

当前版本0.1.0-alpha.4。LAB默认打开核心设计台；“实验与教学”提供课程、原文和辅助实验。设计台可以在没有SoC时使用。

## 创建、验证与复用

1. 在“我的设计”选择CPU、GPU、NPU或ISP并新建。名称与参数自动保存；复制可保留对照方案。
2. 在结构图选择模块，编辑右侧硬件参数。初级模式折叠专家参数，展开后可以查看全部数值。模式切换不改变硬件。
3. 点击“验证核心”。固定向量检查多类功能与资源任务；在“我的测试台”另行改变程序、矩阵或测试帧，观察周期和输出。
4. 验证通过后“发布到IP库”。发布内容不可变，硬件或名称修改后需重新发布；测试输入变化不产生新核心。
5. 导出`.cor`，或建立研究沙盒SoC后“加入当前SoC”。不同CPU ISA不能直接混入同一应用集群；需要替换时勾选替换集群。
6. 导出`.sil`分享SoC。核心定义随文件携带，接收者可在设计台IP页找到“当前SoC内嵌”核心，建立编辑草稿或导出`.cor`。

未验证、参数组合无效的设计仍能保存为草稿；不能发布为已验证IP。通过验证表示本模型的固定测试通过，范围见下表。

## 四类硬件的设计约束

| 核心 | 设计内容 | 验证/观察 | 当前边界 |
| --- | --- | --- | --- |
| CPU | RV32、IA-32、AArch64子集；RV32 M/Zbb；顺序/乱序；共同前端/提交宽度；在途队列；ALU、流水乘除资源；缓存容量/路数/行长与延迟 | 加法访存、相关链、独立整数、分支、已启用扩展；寄存器与调度时序 | 顺序功能解释器先产生轨迹，无投机恢复、有限物理寄存器、多hart一致性、OS或二进制取指 |
| GPU | SIMT处理器、lane宽度、驻留warp、ALU延迟、发射间隔、时钟和带宽 | FP32 AXPY、统一分支和交替分支；逐lane输出、warp调度 | 每处理器单向量发射，路径串行；无完整GPU ISA、图形流水线、寄存器占用分析或驱动 |
| NPU | 阵列行列、INT8/16、INT16/32/64累加器、scratchpad、时钟和带宽 | 手算GEMM、8×8资源任务、累加器wrap边界；实际tile占用 | 无K方向切块、自动编译映射、稀疏、浮点或量化标定；过大测试tile会显示容量不匹配 |
| ISP | 黑电平、标量增益、双线性去马赛克、幂gamma旁路；量化位宽、并行度、最大行宽、时钟和带宽 | 常量帧、渐变形状/范围；图像、行缓冲和传输周期 | RAW12/RGGB教学输入，无MHC、AE/AWB、完整sRGB或画质基准；关闭去马赛克时显示RAW灰度 |

## 可复现的设计比较

CPU先设取指/分派/提交宽度4、总发射宽度4，其余保持默认。在测试台输入以下完整24条独立指令：

```text
ADDI x1,x0,1
ADDI x2,x0,2
ADDI x3,x0,3
ADDI x4,x0,4
ADDI x5,x0,5
ADDI x6,x0,6
ADDI x7,x0,7
ADDI x8,x0,8
ADDI x9,x0,9
ADDI x10,x0,10
ADDI x11,x0,11
ADDI x12,x0,12
ADDI x13,x0,13
ADDI x14,x0,14
ADDI x15,x0,15
ADDI x16,x0,16
ADDI x17,x0,17
ADDI x18,x0,18
ADDI x19,x0,19
ADDI x20,x0,20
ADDI x21,x0,21
ADDI x22,x0,22
ADDI x23,x0,23
ADDI x24,x0,24
HALT
```

1个ALU时33周期；4个ALU时15周期，x24均为24。发射宽度或依赖会限制并行收益，ALU数量不等于任意程序的加速倍数。固定验证的“独立整数运算”提供完整同类程序。

GPU保持默认128元素、8-lane、2个处理器、AXPY，将ALU延迟设为8。每处理器驻留1个warp时计算128周期，驻留4个时35周期；两者传输均96周期。驻留独立warp能隐藏ALU延迟，不能消除外部传输时间。这里的周期来自教学调度假设，不能当作真实GPU的测量数据。

NPU逐渐增加测试台K，比较`scratchpad_bytes`与硬件容量。在当前单tile模型中，tile输入/输出需`(r×K + K×c)×输入字节 + r×c×累加字节`。硬件至少容纳整个阵列K=1的一次输入和累加；更长K仍可能超出容量。不要把一个超容量测试的周期当作可执行硬件结果。

ISP复制两个设计，分别启用/旁路去马赛克。结构图中的去马赛克和两行缓冲会随定义变化；必要量化模块一直存在。比较RGB与RAW灰度、行缓冲容量和周期，不能由灰度预览推导相机色彩质量。

## 文件与估算

新`.cor`保存`design.schema/hardware`，SHA-256身份包含类别、名称和硬件，不包含测试输入、版本或验证分数。导入会重建测试映射、运行固定验证。旧实验配置资产可导入并转换为硬件草稿，原资产保留。

SoC的`.sil`同时保存模板快照与自定义核心，多个实例共享一份定义。模板目录更新不会覆盖已导入的快照。摘要只检出内容失配，不认证厂商资料；模板仍是游戏参数，不能据此还原厂商RTL。游戏版本、格式版本与模型版本分别保留以帮助诊断。

结构图是按已实现资源生成的逻辑图。当前没有任意门级连线编辑、玩家RTL生成、真实综合或PDK签核。CPU面积/功耗/Fmax和GPU/NPU/ISP的SoC映射系数都是未校准教学假设；模型版本变化可能使估算变化。可运行指令语义与论文支持范围见[实验手册](LAB_MANUAL.md)、[来源](REFERENCES.md)；PPA假设见[MODEL.md](MODEL.md)，文件结构见[FORMAT.md](FORMAT.md)。

## 性能套件与x86教学模板

运行CPU性能套件可分别看独立流、依赖链、cache重用和乘法，显示提交指令/周期/IPC、当前硬件与基线对照。不能由默认5指令访存样例判断普遍性能；同瓶颈下不敏感参数可以得到相同IPC。

x86工作站的三种教学模板有明确硬件定义，可从架构页复制到LAB编辑；它们是32位IA-32模型，不是Intel/AMD实物复刻或64位x86实现。当前仅源码脚本启动，安装/分享见玩家手册。
